# Аудит активности пользователей и обнаружение инцидентов

- Запуск и первичная настройка кластера
   ```bash
   cd ./task6/scripts/
   ./start_cluster.sh
   ```
   В процессе применяется модифицированная [audit-policy.yaml](./audit-policy.yaml).  
   Исходная версия из лекций оказалась неработоспособной из-за "\" и "*".

- Запустите выгрузку логов в файл ./task6/logs/audit.log и оставьте её работать
    ```bash
    cd ./task6/scripts/
    ./run_log_monitor.sh
    ```

- В <u>новом терминале</u> запустите скрипт симуляции инцидентов:
    ```bash
    cd ./task6/scripts/
    ./simulate_incident.sh
    ```

- После завершения скрипта симуляции инцидентов завершите выгрузку логов: _Ctrl+c_ в <u>первом терминале</u>.

- Запустите скрипт парсинга логов:  
    <u>Внимание! Скрипт затирает файл с результатами прошлого парсинга.</u>
    ```bash
    cd task6
    python3 -m audit_log_parser
    ```  
    <details>
    <summary>Работа скрипта</summary>
    Состоит из двух фаз:<br>
    1. Проход по всему исходному логу с целью поиска подозрительных записей и сохранение их AuditID.<br>
    2. Проход по всему исходному логу и сохранение всех сообщений с подозрительными AuditID в выходной файл.<br>
    Такая схема позволяет получить более полную картину потенциального инцидента, выдавая весь набор записей, а не только подозрительную.<br>
    Критерии подозрительности сформированы на основе указанных в задании.
    </details>

- Результаты его работы можно в файле [audit_parsed.json](./logs/audit_parsed.json)

- Анализ подозрительных записей в логе аудита активности находится в [analysis.md](./analysis.md)
