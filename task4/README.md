# Защита доступа к кластеру Kubernetes

- [Описание ролевой модели](./rbac.md)
- Запуск minikube
    ```bash
    cd task4/scripts
    ./start_cluster.sh
    ```
- Создание пользователей. Выбран наиболее простой способ добавления пользователей на основе [статического конфига токенов](https://kubernetes.io/docs/reference/access-authn-authz/authentication/#static-token-file) так как в лекциях нет примеров, а в задании нет требований о способе. Однако я понимаю, что для production-окружения он не подойдет.
    ```bash
    cd task4/scripts
    ./create_users.sh
    ```
- Создание ролей
    ```bash
    cd task4/scripts
    ./create_roles.sh
    ```
- Связывание ролей и пользователей
    ```bash
    cd task4/scripts
    ./bind_users_roles.sh
    ```
- Проверка прав созданных пользователей. Тест не является всеохватывающей проверкой корректности, скорее smoke-набор того, что предыдущие скрипты отработали (созданы роли и привязки, есть доступ к одному из доступных ресурсов, нет доступа к одной из недоступных). В том числе проверяется отсутствие доступа к ресурсам чужого namespace для не кластерных ролей.
    ```bash
    cd task4/scripts
    ./check_rbac.sh
    ```
